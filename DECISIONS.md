# Технические решения

## Выбор API

### Яндекс Wordstat

**Проблема:** Старый API Яндекс.Директ (Live v4) требовал одобрения заявки и не работал с корпоративными аккаунтами.

**Решение:** Использован новый **Yandex Search API** (`searchapi.api.cloud.yandex.net`), доступный через Yandex Cloud с API-ключом сервисного аккаунта. Не требует ожидания одобрения.

**Эндпоинт:** `POST /v2/wordstat/dynamics`

---

### HTTP-клиент

**Проблема:** Библиотека `requests` в Python 3.14 не может отправлять заголовки с кириллицей (кодировка latin-1). Токен Яндекса содержит символы вне ASCII.

**Решение:** Использован встроенный `http.client` с явной передачей заголовков как байтов UTF-8. Это обходит ограничение urllib3.

---

## Хранение данных

**Решение:** Google Sheets вместо локального Excel-файла.

**Причины:**
- Данные доступны с любого устройства без скачивания файла
- Несколько человек могут видеть результаты одновременно
- Не нужно вручную передавать файл

---

## Инкрементальное сохранение

**Проблема:** Лимит 100 запросов/час. При 16 неделях × 10 ключевиков = 160 запросов скрипт не укладывается в один час и может упасть на середине.

**Решение:** Каждая неделя записывается в таблицу сразу после сбора. При повторном запуске скрипт читает уже заполненные строки и пропускает их. Можно запускать несколько раз — каждый раз продолжает с того места где остановился.

---

## Обработка ошибок сети

**Проблема:** VPN и корпоративный файрвол периодически обрывают соединение с Google Sheets.

**Решение:** Функция записи повторяет запрос до 5 раз с нарастающей паузой (5 → 10 → 20 → 40 → 80 сек).

---

## Лимит запросов

**Проблема:** API возвращает HTTP 429 при превышении 100 запросов/час.

**Решение:** Фиксированная пауза 37 секунд между запросами (100 запросов × 37 сек ≈ 61 минута). При получении 429 дополнительное экспоненциальное ожидание.

---

## Структура таблицы

**Решение:** Ключевики хранятся в первой строке каждой вкладки начиная со столбца B. Скрипт читает их динамически при каждом запуске — добавление новых ключевиков не требует изменения кода.

Столбец ИТОГО добавляется автоматически после последнего ключевика. При проверке скрипт исключает его из списка ключевиков чтобы не отправлять запрос по слову "ИТОГО".

## Регион

GeoID `11176` — Тюменская область (без Ханты-Мансийского и Ямало-Ненецкого автономных округов).

Проверялись варианты: `11316` (неверный), `55` (Омская область), `11176` (корректный).
